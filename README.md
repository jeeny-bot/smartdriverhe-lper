# 콜비서 일지 — 웹 버전 (테스트용)

대리기사용 앱의 웹 시제품입니다. 두 축으로 이루어져 있어요.

1. **콜지도** — 내 위치(GPS) 기준으로 콜이 많이 나오는 곳을 추천하고, 도착지가 콜밭인지 오지인지 알려줍니다.
2. **일지·가계부** — 콜카드 스크린샷을 올리면 글자를 읽어(OCR) 일지·손익이 자동으로 만들어집니다. 이 콜카드의 출발지가 곧 콜지도의 데이터가 됩니다.
안드로이드 MVP와 같은 기능이며, 실제 콜카드로 먼저 시험해 보고 규칙을 고친 뒤 앱으로 옮기기 위한 버전입니다.

## 실행 방법 (VS Code)

1. Node.js 18 이상을 설치합니다 (https://nodejs.org).
2. VS Code로 이 폴더를 열고 터미널(Ctrl+`)에서:
   ```
   npm start
   ```
3. 터미널에 나온 주소를 브라우저로 엽니다.
   - 컴퓨터: `http://localhost:8080`
   - **폰** (같은 와이파이): 터미널에 함께 나오는 `http://192.168.x.x:8080`

핵심 로직 테스트: `npm test` (55개)

> 폰에서 `192.168...` 같은 http 주소로 열면 "복사" 버튼 등 일부 기능이 예전 방식으로 동작합니다. 정상입니다.
> 실제 폰으로 상시 쓰려면 나중에 https 호스팅(Netlify, GitHub Pages 등)에 올리면 됩니다. 서버가 필요 없는 정적 파일입니다.

## 쓰는 법

1. 폰에서 콜카드를 스크린샷으로 찍습니다.
2. 앱 홈에서 **콜카드 스크린샷 올리기**를 눌러 그 사진을 고릅니다 (여러 장 가능). 컴퓨터에서는 끌어놓기·붙여넣기(Ctrl+V)도 됩니다.
3. 몇 초 뒤 일지에 저장되고, 출발/도착/요금/수수료/순수익이 보입니다.
4. 틀린 곳은 눌러서 고치세요. **고친 내용과 OCR 원문**이 파서를 개선하는 재료가 됩니다.

웹은 스크린샷 자동 감지(백그라운드)를 할 수 없어서 "올리기" 방식입니다. 자동 감지는 안드로이드 앱의 몫입니다.

## 콜지도 쓰는 법

1. **콜지도** 탭 → **테스트 데이터 넣기**를 누르면 가짜 콜 300건이 들어가 지도·추천이 어떻게 보이는지 바로 확인할 수 있어요. (끝나면 "테스트 데이터 지우기")
2. **내 위치 찾기**(GPS). 컴퓨터는 `localhost`에서 되고, 폰은 `https` 주소여야 위치가 허용돼요. 안 되면 지도를 움직여 **지도 가운데를 내 위치로**를 쓰세요.
3. 추천 지역은 **가까울수록·같은 시간대일수록·최근일수록** 높게 점수를 줘요. "시간대"에서 1~3시간 뒤도 볼 수 있어요.
4. **지도를 누르면** 그 지점을 도착지로 보고 **콜밭 / 보통 / 오지 주의**를 판단하고, 가장 가까운 콜밭, **함께가기 문구 복사**, **택시 호출 앱 열기**가 나와요. 일지에서 콜을 눌러 "도착지 착지 분석"으로도 열 수 있어요.
5. 내 콜의 출발·도착 **주소는 자동으로 좌표로 바뀌어** 지도 데이터가 돼요. 이때 **주소 글자가 외부 지도 검색 서버(기본 OpenStreetMap)로 전송**되므로 처음에 동의를 받아요. 이름·전화번호·이미지는 보내지 않아요.
6. **다른 기사님과 공유**: 콜카드를 저장하면 "이 콜 위치를 공유할까요?"가 떠요. 무엇이 공유되는지(예: *수원시 팔달구 인계동 부근 · 10/17(토) 13시대*)를 보여 주고, **공유하기 / 이번엔 안 함 / 앞으로 자동 공유** 중에서 고르면 돼요. 공유한 콜은 일지에 "공유됨" 표시가 붙고, 다른 기사들이 올린 콜 위치는 5분마다(또는 콜지도의 "지금 새로고침") 받아서 추천에 합쳐져요. 공유 방식은 설정 → 공유에서 바꿀 수 있어요.
7. **파일로 주고받기**: 서버가 없을 때는 콜지도 탭 → "서버 없이 파일로 주고받기"를 쓰세요.

### 여러 명이 같이 쓰려면 — Firebase 설정 (처음 한 번, 약 15분)

공유 데이터는 **Firebase(Firestore)** 에 저장하고, 앱 화면은 **Firebase Hosting**(https 주소)으로 올리면 폰에서 GPS도 잘 돼요. 무료(Spark) 요금제로 시작할 수 있어요.

1. **웹 앱 등록 → 설정값 복사**: Firebase 콘솔 → `driver helper` 프로젝트 → 프로젝트 개요의 **앱 추가** → 웹(`</>`) → 닉네임 입력 → **앱 등록**. 화면에 나오는 `firebaseConfig` 중 **apiKey** 와 **projectId** 두 값을 이 폴더의 `js/firebase-config.js` 에 붙여넣고 저장해요. (apiKey는 비밀번호가 아니라 프로젝트 식별값이에요. 접근은 아래 규칙이 막아요.)
2. **익명 로그인 켜기**: 왼쪽 **보안 → Authentication → 시작하기 → 로그인 방법 → 익명 → 사용 설정 → 저장**.
3. **데이터베이스 만들기**: 왼쪽 **데이터베이스 및 스토리지 → Firestore Database → 데이터베이스 만들기** → 위치는 `asia-northeast3 (서울)` → **프로덕션 모드**로 시작 → 만들기.
4. **규칙 올리기**: Firestore → **규칙** 탭의 내용을 지우고 이 폴더의 `firestore.rules` 파일 내용을 전부 붙여넣은 뒤 **게시**. (7번의 `firebase deploy`를 하면 이것도 자동으로 올라가요.)
5. **앱에서 확인**: `npm start` → 브라우저에서 콜지도 탭 → 공유 칸의 **연결 테스트**. `✓ 연결 테스트 성공`이 나오면 끝이에요. 실패하면 어디가 문제인지 한국어로 알려 줘요.
6. **혼자 먼저 시험**: 콜카드를 올려 저장 → "공유하기". 다른 브라우저(또는 시크릿 창)에서 앱을 열고 콜지도 탭을 보면 그 점이 "다른 기사님 콜"로 들어와요.
7. **기사들이 쓰게 올리기(호스팅)**: 터미널에서
   ```
   npm install -g firebase-tools
   firebase login
   firebase use --add        ← driver helper 프로젝트를 고르세요 (.firebaserc 가 채워져요)
   firebase deploy
   ```
   끝나면 `https://<프로젝트ID>.web.app` 주소가 나와요. 그 주소를 기사들에게 알려 주세요. 코드를 고치면 `firebase deploy` 를 다시 하면 돼요.

### Cloudflare Pages 로 배포하기 (Firebase Hosting 대신)

화면 파일만 올리면 되고, 공유 데이터는 계속 Firebase(Firestore)에 저장돼요. 위 Firebase 설정 1~5번을 끝낸 뒤에 하세요. (7번 호스팅은 건너뛰어도 돼요)

1. `js/firebase-config.js` 에 apiKey·projectId 를 채운 상태에서 터미널에 `npm run build` (또는 `node scripts/build-web.mjs`). **dist** 폴더가 생겨요. 화면에 필요한 파일만 들어가서 `test/`·`server/` 같은 건 올라가지 않아요. (설정이 비어 있으면 멈추고 알려 줘요)
2. Cloudflare 대시보드(dash.cloudflare.com) 가입 → **Workers & Pages → 만들기 → Pages → 직접 업로드(Direct Upload)** → 프로젝트 이름(영문 소문자, 예: `driver-helper`) → **dist 폴더를 끌어다 놓기 → 배포**.
3. `https://<프로젝트이름>.pages.dev` 주소가 생겨요. 폰에서 열어 콜지도 탭 → **연결 테스트**로 확인하세요.
4. 코드를 고친 뒤에는 `npm run build` → 같은 프로젝트에서 **새 배포 만들기**로 dist 를 다시 올려요.
- 명령어로 올리고 싶으면: `npx wrangler login` 후 `npx wrangler pages deploy dist --project-name driver-helper`
- Firebase 콘솔에서 apiKey 에 "HTTP 리퍼러 제한"을 걸어 두었다면 새 주소(`*.pages.dev`)를 허용 목록에 넣어야 해요.
- Cloudflare Pages 무료 요금제는 제가 알기로 전송량 제한이 없어서, OCR 데이터(약 10MB)를 처음 받는 기기가 많아도 Firebase Hosting 보다 부담이 적어요. (한도는 Cloudflare 문서에서 확인하세요)
- 배포 후 OCR이 안 되면(글자 읽기 실패) 알려 주세요. `.gz` 학습 데이터 파일의 응답 방식 때문일 수 있어요. 제 컴퓨터의 시험에서는 dist 폴더만으로 OCR이 정상 동작했지만 Cloudflare 위에서는 직접 확인하지 못했어요.

**막힐 때**

| 앱에 나오는 말 | 할 일 |
|---|---|
| Firebase 설정이 비어 있어요 | 1번: `js/firebase-config.js` 에 두 값을 넣었는지 |
| apiKey 가 올바르지 않아요 | apiKey 를 다시 복사 (앞뒤 공백 없이) |
| 익명 로그인이 꺼져 있어요 | 2번 |
| Firestore 데이터베이스를 아직 만들지 않았어요 | 3번 |
| Firestore 규칙이 허용하지 않아요 | 4번 (게시했는지) |
| 오늘 무료 사용량을 넘었어요 | 아래 "무료 한도" |

**무료 한도(제가 아는 Spark 기준이라 콘솔에서 꼭 확인하세요)**: Firestore 읽기 하루 5만 건·쓰기 2만 건, Hosting 하루 전송량 약 360MB. 이 앱은 새로 받은 점만 읽도록 해서 읽기를 아꼈지만, **처음 접속하는 기기는 OCR 데이터까지 약 10MB를 내려받아서** 하루 새 사용자가 수십 명을 넘으면 호스팅 전송량이 먼저 찰 수 있어요. 그때는 요금제(Blaze, 한도를 넘을 때만 과금)를 검토하세요.

**지켜지는 것 / 아닌 것**
- 규칙이 강제하는 것: 로그인한 사용자만 읽기·쓰기, 한국 안의 좌표, 출발지(`s`) 종류만, 시각이 최근 90일 이내, 자기 사용자 번호로만 쓰기, **수정·삭제 불가**.
- 못 막는 것: 한 사람이 그럴듯한 가짜 위치를 많이 올리는 것(익명이라 횟수 제한을 걸 수 없어요). 사용자가 늘면 신고·삭제 기능이나 서버 함수(유료 요금제 필요)로 검증을 더해야 해요.
- 오래된 문서는 자동으로 지워지지 않아요. 앱은 최근 60일만 쓰고, 정리는 Firestore의 TTL 기능으로 나중에 설정할 수 있어요.
- **제가 실제 Firebase에는 접속해 보지 못했어요.** 가짜 Firebase 서버로 두 사용자 시나리오와 오류 안내를 시험했고, 실제 연결은 위 5번 "연결 테스트"가 확인해 줘요.

(Firebase 없이 `npm start` 서버만으로도 같은 와이파이 안에서는 공유돼요. `js/firebase-config.js` 를 비워 두면 그 방식으로 동작해요.)

### 알아둘 점 (솔직한 한계)

- **추천·위험도는 모인 데이터만큼만 정확해요.** 15건 미만이면 "판단 불가"로 나와요. 콜밭/오지 기준값(`js/core/hotspot.js`의 `hotRatio`, `remoteRatio` 등)은 **실제 데이터로 맞춰 본 값이 아니라 임시값**이에요. 쓰면서 조정하세요.
- **주소 → 좌표**는 무료 OpenStreetMap 검색이라 상세 번지는 못 찾는 일이 잦아요. 자세한 주소부터 동·읍·면 수준까지 줄여가며 찾기 때문에 보통 동네 단위로는 잡혀요. 1초에 1건씩 처리해서 많으면 시간이 걸려요. 더 정확하게 하려면 설정에서 카카오 REST 키를 넣을 수 있게 해 두었지만 **카카오 방식은 실제 키로 시험해 보지 못했고**, 브라우저에서 직접 호출이 막히면 서버를 거쳐야 해요.
- **택시 호출 앱 주소**(기본 `kakaot://`)는 제가 폰에서 확인하지 못했어요. 안 열리면 설정 → 지도에서 바꾸세요. 택시 호출·함께가기는 **앱을 열거나 문구를 복사**하는 수준이고, 실제 배차나 매칭 서버는 없어요.
- 지도 타일은 인터넷이 필요해요 (OpenStreetMap).

## 개인정보

- 이미지는 이 기기 안에서만 읽고 **저장하지도, 서버로 보내지도 않습니다.** (OCR 엔진과 한국어 데이터가 `vendor/` 안에 포함돼 있어 인터넷 없이도 동작)
- 기록은 이 브라우저의 localStorage에만 저장됩니다. 브라우저 데이터를 지우면 사라지니 **설정 → 백업 파일 내려받기**를 가끔 쓰세요.
- OCR 원문은 전화번호만 지워서 저장합니다. 고객 이름이나 상세 주소는 남을 수 있습니다.

```
index.html, css/        화면
js/main.js              화면 동작 (업로드·일지·통계·설정)

js/ocr.js               브라우저 OCR (Tesseract.js, PSM 6)
js/store.js             localStorage 저장소·백업
js/core/parser.js       콜카드 해석 규칙 ← 실제 샘플로 보강할 곳
js/core/ledger.js       정산·영업일·통계 계산
js/core/hotspot.js      콜 많은 곳 추천·착지 위험도 계산
js/core/geo.js          거리·격자·시간 도우미
js/core/address.js      주소 정리·검색 후보 만들기
js/core/share.js        콜 위치 공유 파일 (익명화)
js/core/demo.js         테스트용 가짜 콜 위치
test/core.test.js       핵심 로직 테스트
vendor/tesseract/       OCR 엔진·한국어 데이터 (Apache-2.0)
vendor/leaflet/         지도 라이브러리 (BSD-2)
server.mjs              의존성 없는 서버 (화면 + 공유 API)
server/share-api.mjs    공유 API (업로드·조회·제한)
js/share-ui.js          공유 팝업·상태·설정
js/share-sync.js        공유 방식 선택·통신
js/share-firebase.js    Firebase(Firestore) 공유
js/firebase-config.js   ← Firebase 설정값을 붙여넣는 곳
firestore.rules         Firestore 보안 규칙
scripts/build-web.mjs   배포용 dist 폴더 만들기
firebase.json           호스팅·규칙 배포 설정
```

## 꼭 알아둘 것

- **파서는 실제 콜카드 7종(법인콜·수입내역·운행상세 등)에 맞춰 보강했습니다.** 핵심인 일자·시간·출발지·도착지를 우선 읽고, 요금 옆 "수익금"이 있으면 차감액(수수료)을 자동 계산합니다. 새 형식이 나오면 설정 → OCR 원문 모아 복사로 보내 주세요.
- 읽지 못하는 대표 사례: 라벨이 아예 잘린 화면(출발지가 없는 카드), 폰트가 특이해 숫자가 깨지는 카드. 이런 건은 "확인 필요"로 표시되니 눌러서 고치세요.
- 카드에 날짜가 없으면(시간만 있는 카드) 스크린샷을 올린 날짜를 씁니다.
- **OCR이 자주 틀리는 것**: `%` 기호를 `9`나 `6`으로 읽는 일이 있어 "수수료 20%"를 놓칠 수 있습니다. 이때는 수수료가 "(수수료 예상)"으로 표시되고, 설정의 수수료율로 계산합니다. 화살표(→)도 가끔 다른 글자로 읽혀 일부는 보정해 두었습니다.
- 콜카드로 인식하지 못한 이미지는 원문을 보여주고 "그래도 저장"을 고를 수 있게 했습니다. 이런 건이 많이 나오면 설정 → **OCR 원문 모아 복사**로 원문을 모아 파서를 고치세요.
- **수수료율 기본값 20%는 임의의 초기값**입니다. 설정에서 본인 수수료율로 바꾸세요.
- 영업일은 자정이 아니라 새벽 6시에 바뀝니다(설정에서 변경).
- 콜 시각은 카드에 적힌 날짜·시간을 쓰고, 없으면 이미지 파일 시각을 씁니다. 틀리면 수정 창에서 고칠 수 있습니다.
